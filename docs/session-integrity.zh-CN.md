# 区分空结果与登录态过期

采集到 0 条数据，可能表示报表确实为空、登录态过期、页面尚未加载完成，或目标内容没有找到。不要把这些情况都记成成功。

## 接受 0 条结果前先检查页面

在新获取的页面状态中核对三项：

1. 最终网址和来源仍是本次获准访问的报表。
2. 同一页面状态中出现该网站专用的已登录标识。
3. 报表已加载完成，并明确显示空状态。

按证据分类：

| 状态 | 证据 | 下一步 |
|---|---|---|
| `AUTH_REQUIRED` | 跳转到登录页、访问被拒，或明确提示登录过期 | 停止操作，让用户通过网站正常流程登录。 |
| `VERIFIED_EMPTY` | 新鲜的已登录标识、目标报表和明确的空状态提示同时存在 | 记录 0 条，并附报表、范围、时间和来源。 |
| `DATA_VERIFIED` | 新鲜的已登录标识、目标报表和可见记录存在，且读取结果一致 | 记录实际读取到的行和来源。 |
| `TOOL_UNHEALTHY` | 页面有记录但提取结果为空，且已配置的只读探针失败 | 保留页面状态；停止或改用获准的读取路径。 |
| `UNKNOWN` | 缺少标识、空白页、加载中、没有安全探针或信号冲突 | 停止；不要报告为 0，也不要把同一状态下的重试当成新证据。 |

标识必须对应正在检查的网站和账号。缓存的用户名、导航成功、工具返回非空或旧检查点，单独都不足以证明登录有效。如果网站提供受支持的登录状态响应，可以将其作为新鲜证据；不要臆造厂商接口。

工具返回空值本身不能说明是哪一层出了问题。一条 [Browser Use 反馈](https://github.com/browser-use/browser-use/issues/5803)描述了页面其他读取仍有效、但 JavaScript 求值通道静默返回空字符串的情况。另一条 [Playwright MCP 反馈](https://github.com/microsoft/playwright/issues/41617)后来由作者更正：后续调用可以恢复，但有些 Agent 会在首次断连错误后放弃原会话。这些案例用于区分登录态、页面与工具通道；它们不能证明问题发生频率，也不代表所有浏览器栈都会出现相同行为。

## 操作边界

- 让用户通过网站正常流程完成登录、多重验证或 CAPTCHA。
- 不要把密码、Cookie、Bearer Token 或浏览器状态文件写入提示词、截图、日志或公开证据。
- 分类当前页面前，不要刷新、重试或切换账号。
- 每个网站的登录标识需要单独确认；通用提示词不能证明某个标识适用于所有网站。
