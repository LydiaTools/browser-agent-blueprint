# 按钮已经点了，回复却丢了

浏览器工具报错时，页面可能已经保存成功。这个时候，Agent 该再点一次吗？

这个例子来自 [agent-browser 的真实问题 #2032](https://github.com/vercel-labs/agent-browser/issues/2032)。在[上游修复](https://github.com/vercel-labs/agent-browser/pull/2085)之前，如果后台回复丢失，CLI 可能重复发送操作。修复后，它会区分结果未知的操作与可安全重试的读取。问题的发现、补丁和修复归功于上游报告者与维护者。

我们另外做了一个本地实验，让差异看得见。在 macOS 上使用全新的 Chrome 会话和虚构页面，结果是：

| agent-browser 版本 | 后台收到的点击指令 | 本地服务器收到的保存次数 | CLI 返回 |
| --- | ---: | ---: | --- |
| 0.38.2 | 5 次 | 5 次 | 重试后报错 |
| 0.41.0 | 1 次 | 1 次 | `outcome_unknown`（结果未知） |

脚本只发起一次点击。本地代理让点击到达后台，等后台回复后故意丢弃回复；虚构服务器记录实际收到的保存请求。这模拟的是特定的回复丢失场景，不是慢服务器或真实超时测试；结果只适用于本次 macOS 环境和这两个版本。

**更稳妥的下一步，是先核对结果，再决定是否重试。** 新版告诉你结果未知，但不会告诉你是否保存成功；本实验通过服务器计数确认收到了一次保存。实际任务需要选择合适的独立回读方式并记录证据，查不到或结果含糊时仍可能需要人工判断。这个实验和上游修复都不能保证所有操作恰好执行一次。

## 自己运行

本次在 macOS、Node 24.22.1 和 Google Chrome 下测试，使用脚本新建的本地服务器、浏览器会话、套接字代理和临时配置，不连接你的登录浏览器、真实账号或模型 API。其他系统和浏览器尚未验证。

安装并运行的完整命令见[英文版](agent-browser-lost-reply.md#run-the-experiment)。它从 npm 下载指定版本，脚本会核对版本和次数，并关闭自己创建的会话。安装包目录会保留供检查；如果启动或清理失败，脚本会显示保留的临时路径。旧版本请放在隔离环境中，不要用于真实账号。

上游项目已经修复重试问题；Browser Agent Blueprint 提供的是复现实验和“操作后回读”的工作流，不会自动控制 agent-browser。实验在当前源码中，较早的 v0.2.5 ZIP 不包含它。
